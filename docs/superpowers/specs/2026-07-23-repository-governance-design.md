# 安信伴老单人仓库治理设计

## 1. 文档状态

- 日期：2026-07-23
- 状态：已确认，待实施
- 适用仓库：`mago11024/ElderTrust`
- 维护模式：单人维护

## 2. 目标

在不引入多人审批阻塞的前提下，为项目建立可追踪、可回退、可逐步加严的 GitHub 协作规则：

- `main` 始终代表稳定、可继续开发的项目基线；
- 日常变更从最新 `main` 创建独立分支，并通过 Pull Request 合入；
- 防止误删主分支、强制推送和绕过变更记录；
- 用 Milestone 和 Issue 管理 M1 工作及验收条件；
- 在 CI 建立后，把自动检查升级为合并门禁。

## 3. 不在本次范围

- 不强制他人审批，因为仓库当前只有一名维护者；
- 不在没有 CI 工作流时配置必需状态检查；
- 不擅自选择开源许可证；
- 不创建发布、部署或依赖更新自动化；
- 不修改业务需求、技术架构或 M1 功能范围。

## 4. 当前文档 PR 的处理

现有 PR `#1` 采用以下流程：

1. 验证分支工作区干净，文档链接、需求编号和 Git 差异检查通过；
2. 将 PR 从 Draft 转为 Ready for review；
3. 由维护者完成自检，不提交无效的自我批准；
4. 使用 Squash Merge 合入 `main`；
5. 删除远端 `codex/project-documentation` 分支；
6. 本地切换到 `main`，以快进方式同步远端；
7. 后续分支全部从该最新 `main` 创建。

Squash Merge 用于让文档基线在 `main` 上形成一个清晰提交，同时保留 PR 中的完整讨论和原始提交记录。

## 5. `main` 分支治理

为 `main` 建立轻量 Ruleset：

- 状态为 Active；
- 目标为默认分支 `main`；
- 禁止删除分支；
- 禁止非快进更新和强制推送；
- 要求变更通过 Pull Request；
- 必需批准数为 `0`；
- 要求合并前解决所有 PR 对话；
- 暂不要求状态检查；
- 仓库管理员不设置常规绕过入口。

当首个稳定 CI 工作流合入后，再单独更新 Ruleset，要求相应状态检查成功。不得预先绑定尚不存在或名称不稳定的检查。

## 6. 分支与合并约定

- 功能：`feature/<topic>` 或 `codex/<topic>`
- 修复：`fix/<topic>`
- 文档：`docs/<topic>`
- 测试：`test/<topic>`
- 工程治理：`chore/<topic>`
- 安全：`security/<topic>`

每个分支必须从最新 `main` 创建。Pull Request 默认使用 Squash Merge；需要保留独立提交历史的特殊变更，可在 PR 中说明后改用 Rebase Merge。禁止对共享分支强制推送。

## 7. M1 任务治理

创建一个开放的 `M1：文字训练核心` Milestone，并建立以下首批 Issues：

1. 工程骨架与版本锁定；
2. MySQL 与 Alembic 基线；
3. 客服退款 L4 场景配置与校验；
4. L4 训练状态机；
5. 行为事件与确定性规则评分；
6. 训练会话 API 与统一错误格式；
7. 老人端文字按钮主流程；
8. M1 验收测试与 CI。

每个 Issue 至少包含：

- 目标和范围；
- 明确的不包含内容；
- 可验证的完成条件；
- 关联需求编号；
- 依赖关系；
- 安全、隐私或降级影响。

单人维护模式下不虚构多个负责人，Issue 默认由仓库所有者负责；开始实施时再设置具体状态和优先级。

## 8. 仓库安全与所有权

保留当前已启用的 Secret Scanning 和 Push Protection。

许可证暂不添加。正式允许他人复制、修改或分发代码前，由所有者明确选择许可证；在此之前，不把公开可见等同于已授权开源。

`SECURITY.md`、Issue 模板、`.gitignore`、`.editorconfig`、`.env.example` 和 CI 工作流属于下一份工程治理 PR，由新 `main` 创建独立分支提交，避免继续扩大文档基线 PR 的范围。

## 9. 实施顺序

```text
确认本设计
→ 更新并复核 PR #1
→ Ready for review
→ Squash Merge 到 main
→ 同步本地 main
→ 创建并启用 main Ruleset
→ 创建 M1 Milestone 和 Issues
→ 从新 main 创建工程治理分支
```

## 10. 验证标准

实施完成后必须验证：

- PR `#1` 状态为已合并且基分支为 `main`；
- 远端和本地 `main` 指向同一个合并提交；
- `main` 显示为受 Ruleset 保护；
- Ruleset 不要求他人批准，也不引用不存在的状态检查；
- `M1：文字训练核心` Milestone 存在且为开放状态；
- 八个 M1 Issues 均关联该 Milestone；
- 新工程分支的起点是合并后的 `main`；
- 工作区没有未提交改动。
