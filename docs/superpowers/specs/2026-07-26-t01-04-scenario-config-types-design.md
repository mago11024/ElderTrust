# T01-04 场景配置类型设计

## 1. 文档状态

- 日期：2026-07-26
- 状态：已确认
- Task：T01-04
- 依赖：T01-01、T00-03
- 交付目标：用严格的 Pydantic 类型表达客服退款 V1 场景配置，并用机器可读种子证明配置可加载和校验

## 2. 范围

本 Task 创建 `backend/app/scenarios/schemas.py`、
`backend/app/scenarios/seeds/customer_refund_v1.json` 和
`backend/tests/unit/scenarios/test_schema.py`。

本 Task 负责：

- 定义场景、阶段、选择、转换、行为映射、结束条件和评分策略类型；
- 表达固定话术、AI 策略、风险点、安全行为、禁止内容、敏感信息规则、压力限制和降级内容；
- 加载并校验客服退款 V1 JSON；
- 拒绝缺少必填字段、错误 UUID v4、非法枚举和未知字段的配置。

本 Task 不负责图可达性、未知转换目标、循环、结束路径、数据库版本、HTTP API、状态机执行或评分计算。
图级和跨对象引用校验属于 T01-05。

## 3. 方案选择

采用多个职责单一的嵌套 Pydantic 模型。所有配置模型禁止未知字段，枚举使用稳定的英文
`snake_case` 值。相比单一大模型或宽松字典，这种结构能在加载边界尽早发现契约错误，同时为 T01-05
提供明确、可复用的类型输入。

## 4. 配置结构

顶层 `ScenarioConfig` 包含：

- 契约身份：`schema_version`、`scenario_id`、`scenario_version_id`、`scenario_key`、
  `scenario_version`、`title` 和 `runtime_level`；
- 流程入口：`initial_stage_id` 和 `stages`；
- 全局安全入口与结束定义；
- 内容安全限制与 L4 降级内容；
- 确定性评分策略。

`scenario_id` 和 `scenario_version_id` 使用固定 UUID v4。`scenario_key` 使用稳定的
`snake_case` 字符串，`scenario_version` 和 `schema_version` 为正整数。训练开始后的版本锁定由后续
训练 Task 执行，本 Task 只保证配置具备所需版本身份。

### 4.1 阶段和选择

每个阶段包含稳定阶段 ID、顺序、标题、固定话术、受控 AI 策略、风险点和普通选择。每个普通选择包含：

- 稳定选择 ID 和按钮文案；
- 一个结构化转换目标；
- 一个或多个行为事件映射。

行为映射记录事件类型、评分维度、方向、严重度、固定机会点和脱敏证据摘要。阶段 4 的敏感操作选择用两条
独立映射表达信息保护和支付警觉事件，不让一条事件占用两个机会点。

转换只保存目标种类和目标 ID。Schema 校验字段形状和枚举，不在本 Task 判断目标是否存在。

### 4.2 安全与结束

两个全局安全选择分别表达 `end_training` 和 `suspected_real_fraud`，生成不参与评分的控制事件并转换到
`safety_stopped`。结束定义包含 `completed_safe`、`completed_risky` 和 `safety_stopped`，并以结构化
条件表达普通完成、安全中止和严重风险覆盖的契约。

内容安全配置要求提供：

- 禁止内容；
- 敏感信息规则；
- 压力限制；
- 疑似真实受骗时的安全提示；
- 不自动报警、不自动冻结资金、不自动联系家属的外部动作限制。

### 4.3 评分策略

评分策略以配置形式保存五个维度、固定机会点、整数权重、正负机会点分、严重负向维度封顶和整数舍入策略。
客服退款 V1 的权重固定为 `20, 25, 25, 15, 15`。

Schema 只验证单个字段类型、取值范围以及适合字段边界表达的局部约束。事件目录一致性、机会点完整性和
评分执行由后续评分 Task 负责，避免在 T01-04 提前实现业务引擎。

## 5. 加载与失败行为

种子通过 `ScenarioConfig.model_validate_json(...)` 加载。有效 JSON 返回完整类型化配置；无效 JSON
抛出 Pydantic `ValidationError`，不静默填充业务必填字段，也不接受未知字段。

客服退款 V1 种子完整表达 T00-03 已锁定的五个阶段、全部普通选择、两个全局安全入口、行为映射、三种
结束状态、五维评分策略、安全限制和 L4 降级内容。种子中的场景与版本 UUID 固定不变，保证测试和后续
开发引用稳定。

## 6. 测试设计

严格遵循红—绿—重构：

1. 先写有效种子加载测试，确认因模型或种子尚不存在而按预期失败；
2. 实现满足该测试的最小类型和种子；
3. 写删除必填字段后的失败测试，确认 Pydantic 明确拒绝；
4. 补充关键契约测试，覆盖固定 UUID v4、未知字段、非法枚举和正整数版本约束；
5. 运行聚焦验收、受影响后端检查和一次最终完整回归。

测试不断言图可达性、未知目标或有限结束路径，避免越过 T01-05 边界。
