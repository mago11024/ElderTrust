# T01-06 纯领域训练状态机设计

## 目标与边界

实现不依赖 FastAPI、数据库和 AI 的纯领域训练状态机，使固定学习与后续动态测评复用同一套场景阶段、选择、事件和结束条件。

本 Task 覆盖正常完成、用户主动结束、场景版本锁定、最大轮次防御、重复选择幂等和客服退款全部配置路径的有限结束证明。不包含安全关键词识别、持久化、HTTP、最终评分或 AI 编排。

## 方案

采用不可变领域状态和纯转换函数。转换函数只接收场景配置、当前状态和选择命令，返回新的状态与转换结果，不读取或修改外部状态。

相较于可变领域对象，该方案更容易证明重复请求不会重复推进或生成事件；相较于通用字典式 reducer，该方案保留明确的 Python 类型和领域约束。

## 领域模型

`backend/app/training/domain.py` 定义：

- 不可变训练状态，包含锁定的 `scenario_version_id`、当前阶段、轮次、累计事件、结束状态和已处理请求结果；
- 选择命令，包含唯一请求 ID、当前阶段、选择 ID 和场景版本 ID；
- 转换结果，包含处理后的状态、本次产生的行为事件或控制事件，以及是否命中幂等结果；
- 明确的领域错误，区分版本不匹配、阶段不匹配、未知选择、已结束、最大轮次和请求 ID 冲突。

训练开始时从配置创建初始状态，并锁定配置的 `scenario_version_id`。后续命令必须引用同一版本。

## 转换规则

`backend/app/training/state_machine.py` 提供纯函数处理选择：

1. 先检查请求 ID 是否已处理。同一请求 ID 和相同命令返回第一次的同一结果，不推进状态也不重复生成事件；同一请求 ID 携带不同命令时报冲突。
2. 检查会话未结束、场景版本一致、阶段一致且未超过最大轮次。
3. 全局安全选择优先于普通选择处理。`end_training` 立即进入 `safety_stopped`，保留 `end_reason=user_ended`，并产生不参与评分的控制事件。
4. 普通选择从当前阶段配置中解析，复制其确定性行为映射，并按目标进入下一阶段或结束状态。
5. 普通结束时检查累计事件是否命中配置中的风险覆盖条件。命中时将普通结束候选改为 `completed_risky`；否则保留配置目标。
6. 结束后的任何新请求均被拒绝，不产生新事件。

最大轮次由已校验配置的阶段数量推导，只作为防御性上限。若异常状态在达到上限后仍未结束，转换被拒绝，不新增结束状态，也不把异常会话误标为正常完成。

## 测试设计

`backend/tests/unit/training/test_state_machine.py` 先以失败测试覆盖：

- 客服退款安全路径正常完成；
- 严重负向事件将最终安全候选覆盖为 `completed_risky`；
- 任意阶段通过 `end_training` 主动结束；
- 场景版本在训练开始后保持锁定；
- 达到最大轮次后拒绝继续转换且不生成事件；
- 相同请求重复提交返回同一结果，不重复事件；
- 相同请求 ID 携带不同选择时报冲突；
- 遍历客服退款场景全部普通配置路径，断言每条路径都在阶段数上限内结束。

实现阶段先运行聚焦测试，最终候选版本运行 Task 验收命令、受影响场景模块回归和一次完整回归。
