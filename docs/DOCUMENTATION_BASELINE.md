# 文档基线与决策

## 1. 基线说明

本文件记录 2026-07-23 文档统一后的有效项目基线，用于避免旧方案、概览文档和后续实现彼此覆盖。

当前有效结论：

- 第一版聚焦老人反诈训练、家庭协同和双场景验证；
- 社区共育是长期产品方向，不进入第一版功能验收；
- 后端采用 Python 3.12、FastAPI 和模块化单体；
- 前端采用 Vue 3、TypeScript 和手机优先 PWA；
- 最终评分由确定性规则计算，AI 只辅助理解和表达；
- 第一版不包含真实电话、完整全双工、声音克隆和自动报警；
- 工程尚未建立，文档中的目录、命令和环境变量均为待落地契约，不代表现有能力。

## 2. 本次解决的旧新冲突

| 主题 | 旧文档方向 | 当前有效方向 |
| --- | --- | --- |
| 第一版中心 | 课程、家庭、社区共育并行 | 训练核心优先，家庭闭环随后，社区后置 |
| 后端技术 | Java 17、Spring Boot 3、MyBatis-Plus | Python 3.12、FastAPI、SQLAlchemy 2 |
| AI 与语音 | 非第一版必要能力 | 第一版核心创新能力，但必须受控且可降级 |
| 用户角色 | 老人、家属、社区工作者、管理员 | 老人、家属、内容管理员、系统管理员 |
| 第一版终端 | 多角色后台和社区工作台 | 老人端、家庭端、轻量管理端 PWA |
| 内容范围 | 社区活动、课程、群体统计 | 客服退款旗舰场景、保健品扩展场景 |
| 评估方式 | 训练结果和统计为主 | 带证据的行为事件、规则评分和五维复盘 |
| 部署目标 | 通用 Web 系统 | 公网手机演示 + 不依赖公网 AI 的本地降级包 |

旧提交仍属于项目历史，但不得作为第一版实现依据。若提交、Issue 或讨论引用旧方案，应链接到本文件并以当前基线重新判断。

## 3. 文档职责

| 文档 | 负责回答 |
| --- | --- |
| `README.md` | 项目是什么、当前状态、从哪里开始阅读 |
| `PROJECT_OVERVIEW.md` | 产品定位、用户、范围和成功标准 |
| `REQUIREMENTS.md` | 可验证的功能与非功能需求 |
| `ARCHITECTURE.md` | 模块、数据流、边界和部署拓扑 |
| `TECH_STACK_AND_CORE_FEATURES.md` | 技术选型及不采用方案 |
| `ROADMAP.md` | 实施顺序和里程碑完成条件 |
| `DEVELOPMENT.md` | 工程落地后的目录、命令和质量契约 |
| `SECURITY_PRIVACY.md` | 数据、授权、AI、语音和上线安全边界 |
| [`AGENTS.md`](../AGENTS.md) | 强制开发规则和文档入口 |
| [`CURRENT_STATUS.md`](CURRENT_STATUS.md) | 当前里程碑、Task、阻塞和最近验证 |
| [完整 Task 目录](superpowers/plans/2026-07-23-complete-project-task-catalog.md) | Task 范围、依赖、文件和验收 |
| [`TASK_CHANGELOG.md`](TASK_CHANGELOG.md) | Task 调整、Bugfix 和 Gate 重验历史 |
| 完整设计规格 | 已确认的跨文档产品与系统设计依据 |
| 本文件 | 方案切换记录、文档优先级和未决事项 |

同一主题出现冲突时，按以下规则处理：

1. 安全与隐私约束；
2. 已编号需求及其验收标准；
3. 已批准设计与架构；
4. 完整 Task 目录；
5. `CURRENT_STATUS.md` 只决定执行位置，不改变 Task 范围；
6. 当前代码、迁移和自动化测试建立后，文档必须与已验证实现同步，不能继续描述计划状态；
7. 无法按上述规则判断时，先创建决策记录，不在多个文档中分别猜测。

## 4. 仍需在开发前或原型后确定的事项

下列内容不是文档冲突，也不应在缺少证据时提前定死：

- ASR、LLM、TTS 的具体供应商、区域、计费和数据保留条款；
- 浏览器录音格式、分片大小和 WebSocket 消息协议；
- 首个语音原型的响应延迟、打断延迟和识别成功率基线；
- 原始录音的默认保留天数及用户延长规则；
- 公网演示环境、域名、证书和数据存放区域；
- 用户协议、隐私告知、训练免责声明和第三方素材许可；
- 团队实际开发设备能否稳定运行完整容器环境。

这些事项的关闭条件见[正式开发前检查清单](PRE_DEVELOPMENT_CHECKLIST.md)。

## 5. 变更规则

涉及以下内容的变更必须同时检查需求、架构、安全和开发文档：

- 第一版范围或角色；
- 技术栈、目录或启动命令；
- 家庭授权和可见数据；
- 场景状态机、评分和 AI 约束；
- 录音、转写、日志和第三方数据传输；
- 降级等级、部署方式和验收标准。

纯措辞调整不需要复制到所有文档，但不得改变上述基线含义。
