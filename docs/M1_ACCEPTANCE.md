# M1 人工验收脚本

## 1. 目的与执行时点

本文定义 M1 客服退款 L4 文字训练 MVP 的四条人工验收路径。它是后续 T01 Task 的稳定验收契约，不表示
当前 M0 已有可运行产品。

- `M1.0` 在 T01-13 执行进程内纵向闭环脚本；
- `M1.1` 在 T01-18 对 MySQL、登录、资源授权、审计集成后的同一流程重验；
- 执行设备以手机尺寸浏览器为主；
- 全部账号、订单和场景数据必须是虚构数据；
- 每次执行记录构建版本、场景版本、执行人、时间、实际结果和证据位置。

脚本中的稳定字段和值遵循
[`DATA_CONVENTIONS.md`](./DATA_CONVENTIONS.md)、
[`API_CONVENTIONS.md`](./API_CONVENTIONS.md)、
[`SCENARIO_CUSTOMER_REFUND_V1.md`](./SCENARIO_CUSTOMER_REFUND_V1.md) 和
[`SCORING_RULES.md`](./SCORING_RULES.md)。

## 2. 通用准备

1. 使用客服退款场景 `customer_refund`、版本 `1`、运行等级 `l4`。
2. 准备老人账号 A；M1.1 另准备无权访问 A 数据的账号 B。
3. 清除本轮虚构训练数据，或创建新的训练会话，避免旧证据影响结果。
4. 记录训练开始时返回的 `training_session_id` 和 `scenario_version_id`。
5. 确认界面始终可见“结束训练”和“我可能正在实际受骗”两个安全入口。
6. 开启浏览器无障碍与网络检查；验收期间不得人工修改数据库或会话状态。

## 3. M1-AC-01 正常完成

**目标：** 证明五阶段固定分支、确定性行为事件、五维评分和个人复盘形成正常闭环。

**执行：**

1. 账号 A 开始一轮新的客服退款 L4 训练。
2. 在 `customer_identity` 选择 `verify_via_official_channel`。
3. 在 `order_anomaly` 选择 `check_order_independently`。
4. 在 `refund_offer` 选择 `require_original_route_refund`。
5. 在 `sensitive_action` 选择 `refuse_sensitive_actions`。
6. 在 `time_pressure` 选择 `pause_and_verify`。
7. 打开个人复盘，并检查本轮证据和评分。

**必须同时满足：**

- 阶段按定义顺序前进，不跳步、不回环，五次普通选择后结束；
- 全部阶段、事件和结果引用开始时锁定的同一个 `scenario_version_id`；
- 七个固定机会点各有且只有一个有效事件；
- 五维分均为 100，`total_score` 为 100；
- 结束状态为 `completed_safe`；
- 复盘至少展示做得好的行为、未识别风险、脱敏证据和一条优先改进建议；
- 证据不包含完整对话、验证码、银行卡号、令牌或其他敏感数据；
- 在手机尺寸下无需开发人员解释即可完成，关键页面只有一个突出的主要下一步操作。

## 4. M1-AC-02 主动终止

**目标：** 证明用户可以在普通流程中随时结束训练，且终止优先于后续角色扮演和评分。

**执行：**

1. 账号 A 开始新的客服退款 L4 训练。
2. 完成第一阶段任一普通选择，进入 `order_anomaly`。
3. 不选择普通按钮，点击全局入口 `end_training`。
4. 刷新结果页；M1.1 另退出并重新登录后再次查看该会话。

**必须同时满足：**

- 点击后立即停止诈骗角色和后续普通转换；
- 结束状态为 `safety_stopped`，`end_reason` 为 `user_ended`；
- 记录一个 `training_ended_by_user` 控制事件，证据来源为 `safety_control`；
- 控制事件不占用评分机会点，不生成五维分或 `total_score`；
- 刷新以及 M1.1 重新登录后状态不被恢复为进行中；
- 页面说明训练已由用户结束，并给出清晰、安全的下一步。

## 5. M1-AC-03 安全中止

**目标：** 证明“可能正在实际受骗”入口立即退出诈骗角色，并进入无自动外联的安全优先流程。

**执行：**

1. 账号 A 开始新的客服退款 L4 训练。
2. 在任意普通阶段点击 `suspected_real_fraud`。
3. 阅读安全页面，并检查本轮结果。
4. 等待至少一个正常前端请求周期，确认没有自动跳转到外部机构或自动发送家属通知。

**必须同时满足：**

- 点击后立即停止诈骗角色和后续普通转换；
- 结束状态为 `safety_stopped`，`end_reason` 为 `suspected_real_fraud`；
- 记录一个 `suspected_real_fraud_declared` 控制事件，证据来源为 `safety_control`；
- 页面明确提醒停止转账、停止提供信息并通过独立官方渠道核实；
- 不生成五维分或 `total_score`；
- 不自动报警、不自动冻结资金、不联系外部机构；
- M1 阶段不自动通知家属；后续家庭通知仍必须满足事先授权和当次确认。

## 6. M1-AC-04 越权拒绝

**目标：** 证明训练会话和个人复盘受资源所有权保护，修改资源 ID 不能读取他人数据。

**执行：**

1. 在 M1.1 环境中，账号 A 完成 `M1-AC-01`，记录其 `training_session_id`。
2. 退出账号 A，以账号 B 登录。
3. 将账号 B 自己可访问页面或请求中的资源 ID 替换为 A 的 `training_session_id`。
4. 分别尝试读取 A 的训练会话、行为事件、评分和个人复盘。
5. 再以账号 A 登录，确认原数据仍完整可见。

**必须同时满足：**

- 账号 B 的每次访问均被拒绝，稳定错误码为 `PERMISSION_DENIED`；
- 错误响应遵循统一结构，`details` 不包含 A 的训练主题、事件、分数、复盘或其他受保护字段；
- 拒绝不会修改、删除或终止 A 的会话；
- 账号 A 仍可读取自己的完整结果；
- 日志不记录密码、令牌、验证码、完整对话或其他敏感内容；
- 审计证据能够关联请求和拒绝结果，但不泄露受保护正文。

## 7. 结果记录与 Gate 判定

每条脚本记录为 `passed` 或 `failed`。只要一个“必须同时满足”项不成立，该脚本即为 `failed`，不得以
备注替代失败。

- T01-13 至少通过 `M1-AC-01`、`M1-AC-02` 和 `M1-AC-03`；
- T01-18 必须在持久化与登录环境重跑前三条，并通过 `M1-AC-04`；
- 失败证据应创建当前 Task 缺陷或独立 Bugfix Task，不降低本文验收标准；
- 自动化测试与本人工脚本都通过后，才能判定对应 M1 Gate 通过。
