# 项目路线图

## 1. 推进原则

项目不以固定开发天数约束第一版，而以可演示、可验证的里程碑推进。每个里程碑都必须形成可运行版本，不能同时铺开多个半成品模块。

实施顺序与最终产品流程不同：开发先验证训练核心，最终产品再呈现家庭陪伴闭环。

## 2. M0：文档基线

目标：让产品、技术和安全边界一致。

完成条件：

- README、需求、架构、技术栈、开发和安全文档一致；
- 后端确定为 FastAPI 模块化单体；
- 第一版明确排除社区端、真实电话和声音克隆；
- 客服退款和保健品营销的角色清楚；
- 完整设计规格已提交。
- 文档基线、冲突处理规则和开发前检查清单已提交；
- 启动阻塞项已确认负责人和关闭方式。

## 3. M1：文字训练核心

目标：不用语音和外部 AI，完成客服退款的最小纵向闭环。

范围：

- Vue 和 FastAPI 工程骨架；
- MySQL 本地基础设施；
- Redis 和对象存储使用明确接口；在首个真实使用者出现前可使用进程内或本地文件测试替身；
- 客服退款结构化场景；
- 统一状态机；
- 文字和按钮交互；
- 行为事件与确定性规则评分；
- 基础个人复盘。

完成条件：

- 用户可从开始走到训练结束；
- 状态机转换和评分具有单元测试；
- L4 模式可以独立运行；
- 数据库迁移可重复执行。

## 4. M2：固定分支语音

目标：形成稳定的语音学习模式。

范围：

- ASR 和 TTS 适配器；
- 自动轮流；
- 固定分支话术；
- 重说、文字确认和按钮降级；
- 语音状态和麦克风权限处理。

完成条件：

- 手机可完成一次语音学习；
- ASR/TTS 失败可自动退回 L3/L4；
- 外部调用具备超时和模拟实现；
- 日志不包含敏感语音内容。

## 5. M3：受控 AI 测评

目标：实现核心创新能力。

范围：

- 动态 LLM 适配器；
- 阶段和策略约束；
- 敏感输入过滤和输出安全检查；
- 五维行为识别；
- 规则评分和证据复盘；
- 疑似真实受骗中止。

完成条件：

- AI 不能自行跳出场景状态机；
- 同一行为的不同表达能映射到相同规则；
- 最终分数不由 AI 直接生成；
- 越界、超时和格式错误触发安全话术与降级。

## 6. M4：家庭闭环

目标：从一次训练扩展为持续改善。

范围：

- 双向邀请和老人确认；
- 分项授权；
- 老人先查看再分享；
- 家庭能力摘要；
- 单任务行动卡；
- 针对性复训。

完成条件：

- 未授权家属无法查看摘要；
- 家属无法连接实时训练；
- 老人撤销后新的访问立即失败；
- 行动卡完成情况不影响老人得分。

## 7. M5：体验增强

目标：完成旗舰答辩体验。

范围：

- 模拟来电界面；
- 客服退款主动打断；
- 多种合成语音角色；
- 训练前设备检查；
- PWA 安装和手机适配。

完成条件：

- 老人开口后 AI 播放及时停止；
- 取消过期生成和合成任务；
- 无麦克风时可进入 L4；
- 关键流程可由老人独立完成。

## 8. M6：第二场景与内容管理

目标：证明训练引擎可扩展。

范围：

- 保健品营销场景；
- 慢节奏信任积累和压力曲线；
- 场景表单、沙盒、审核、发布和下线；
- 不可变版本；
- 脱敏 AI 异常记录。

完成条件：

- 保健品场景复用同一状态机和评分基础；
- 训练引擎没有针对客服退款硬编码；
- 发布检查能够发现缺失结束条件和降级内容；
- 进行中的会话锁定启动版本。

## 9. M7：部署与答辩加固

目标：达到答辩级完整版本。

范围：

- 局域网或临时 HTTPS 手机联调；
- 短期云服务器和公网 HTTPS；
- L3 本地答辩包；
- 性能、权限、安全和可用性测试；
- 演示账号、虚构数据和演示脚本。

完成条件：

- 公网手机可完成客服退款完整闭环；
- 关闭外部 AI 后仍可完成本地演示；
- 保健品场景证明扩展能力；
- 录音自动过期和审计已验证；
- 答辩演示可重复完成。

## 10. 答辩演示路径

```text
家属推荐客服退款训练
→ 老人接到模拟来电
→ 与 AI 对话并主动打断
→ 系统展示五维复盘和证据
→ 老人确认分享
→ 家属收到行动卡
→ 展示保健品场景
→ 关闭 AI 服务并演示降级
```

## 11. 第一版之后

第一版稳定后，按独立设计周期评估：

- 社区活动、任务和匿名群体统计；
- 小程序或原生应用；
- 本地 ASR、TTS 或大模型；
- 更多诈骗场景；
- 可视化场景编排器；
- 外部机构协作。

这些能力不会自动进入第一版，也不能绕过隐私、安全和责任评审。
