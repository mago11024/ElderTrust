# 技术栈与核心功能

## 1. 选型结论

第一版采用：

> Vue 3 PWA + FastAPI 模块化单体 + MySQL 8 + 可替换 AI 服务适配器

选择 FastAPI 的主要原因是核心链路需要频繁等待语音识别、大模型、语音合成和 WebSocket 消息，属于 I/O 密集型编排；使用 Python 也便于统一实现状态机、AI 适配、安全检测和评估逻辑。

Spring Boot、Java、MyBatis-Plus、Maven 和 JUnit 是早期文档方案，不再作为第一版技术基线。

## 2. 前端

| 类型 | 技术 |
| --- | --- |
| 框架 | Vue 3 |
| 语言 | TypeScript |
| 构建 | Vite |
| 路由 | Vue Router |
| 状态 | Pinia |
| UI | 适老化自定义组件，管理端可选 Element Plus |
| HTTP | Fetch 或 Axios，项目内统一封装 |
| 实时通信 | 原生 WebSocket 封装 |
| 单元测试 | Vitest、Vue Test Utils |
| 端到端测试 | Playwright |
| 应用形态 | 手机优先 PWA |

老人端不能简单套用管理后台组件。字体、对比度、点击区域、语音状态和错误恢复需要单独设计。

## 3. 后端

| 类型 | 技术 |
| --- | --- |
| 语言 | Python 3.12 |
| API 框架 | FastAPI |
| 数据校验 | Pydantic |
| ORM | SQLAlchemy 2 |
| 数据库迁移 | Alembic |
| 鉴权 | 短期 JWT、Secure HttpOnly Cookie、资源授权 |
| HTTP 测试 | pytest、FastAPI TestClient / HTTPX |
| WebSocket 测试 | pytest、TestClient WebSocket |
| 服务进程 | Uvicorn，生产环境由容器和反向代理管理 |

后端采用异步 I/O 编排外部 AI 服务。同步阻塞库需要放入线程池或替换为异步客户端；本地重型模型必须放入独立推理进程。

## 4. 数据与基础设施

| 类型 | 技术 |
| --- | --- |
| 主数据库 | MySQL 8 |
| 短期状态 | Redis |
| 音频与素材 | MinIO 或兼容 S3 的对象存储 |
| 反向代理 | Nginx |
| 容器化 | Docker、Docker Compose |
| API 文档 | FastAPI OpenAPI |
| 日志 | Python 结构化日志 |
| 监控预留 | 健康检查、关键延迟和降级指标 |

Redis 不保存唯一业务事实。音频对象必须设置到期时间和删除状态。

## 5. AI 服务

第一版不绑定特定厂商，业务层只依赖三个接口：

- ASR：音频转文本；
- LLM：行为识别、受控回复和复盘表达；
- TTS：文本转语音。

每个适配器必须提供：

- 统一请求和响应类型；
- 超时与取消；
- 错误归一化；
- 健康状态；
- 脱敏和最少数据传输；
- 可测试的模拟实现。

云端服务是正常运行路径，本地固定分支和预录语音是答辩降级路径。

## 6. 核心功能

### 6.1 双模式训练

- 学习模式：固定分支、提示、重听和解释。
- 测评模式：受控 AI 动态对话，结束后统一复盘。

两种模式共用状态机、风险点和评分规则。

### 6.2 统一状态机

状态机决定当前阶段、允许策略、转换条件和结束方式。AI 负责在允许范围内改变语言表达，不负责决定业务流程。

### 6.3 语音交互

- 所有场景支持自动轮流。
- 客服退款场景支持主动打断。
- 第一版不实现完整全双工。
- 识别失败可降级到文字确认和按钮。

### 6.4 可解释评分

最终得分由规则计算，覆盖：

- 身份核实；
- 信息保护；
- 支付警觉；
- 压力应对；
- 求助终止。

AI 负责把不同自然语言映射为带证据的行为事件，并生成易懂复盘。

### 6.5 家庭闭环

- 双向邀请、老人确认绑定；
- 分项授权；
- 老人先查看再分享；
- 家庭行动卡；
- 针对性复训；
- 家属默认不查看完整录音和逐字对话。

### 6.6 内容管理

- 结构化场景配置；
- 沙盒测试和语音试听；
- 草稿、测试、审核、发布和下线；
- 不可变版本；
- 脱敏异常治理。

第一版不做拖拽式低代码编排器。

### 6.7 安全求助

疑似真实受骗时停止角色扮演，提示停止转账和信息提供。只有老人事先授权且当次确认后，才通知指定家属。

## 7. 首批场景

### 客服退款

完整支持固定学习、动态测评、自动轮流、主动打断、五维评分、家庭行动和四级降级。

### 保健品营销

验证慢节奏信任积累、健康焦虑、虚假权威和持续诱导，证明状态机不是为单一客服场景硬编码。

## 8. 第一版暂不采用

### 微服务

当前并发和团队规模不需要服务拆分。模块化单体更有利于快速验证状态机、权限和数据一致性。

### 原生 App 或小程序

手机优先 PWA 可以统一开发并满足扫码演示。后续根据真实使用反馈决定是否迁移。

### 本地大模型作为必需依赖

本地推理会增加硬件和部署压力。第一版采用云端适配器，并准备不依赖 AI 的 L3/L4 降级。

### 社区工作端

第一版先完成个人训练和家庭闭环。社区活动、组织权限和群体统计进入后续设计周期。

### 声音克隆和真实电话

伦理、隐私和通信合规成本过高，不进入第一版。

## 9. 交付顺序

1. Vue/FastAPI 工程骨架和本地基础设施。
2. 文字版客服退款、状态机和规则评分。
3. ASR、TTS、自动轮流和固定分支。
4. 受控 AI 和五维复盘。
5. 家庭授权、分享和行动卡。
6. 模拟来电、主动打断和多语音角色。
7. 保健品营销和内容管理。
8. 公网部署、降级包、安全和答辩验证。

具体完成定义见[项目路线图](ROADMAP.md)。
