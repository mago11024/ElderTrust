# 技术栈与核心功能

## 文档目的

本文档确定“安信伴老”第一版系统的技术栈、核心功能、模块边界和交付路线。它用于指导后续建仓、编码、测试、部署和评审，避免项目在早期陷入技术选择摇摆或功能范围失控。

## 选型结论

第一版采用“Vue 3 前端 + Spring Boot 3 后端 + MySQL 8 数据库”的单体优先架构。

这套方案适合本项目，原因是：

- 业务以用户、权限、课程、训练记录、内容管理和统计为主，典型关系型业务较多。
- Java / Spring Boot 生态成熟，适合权限控制、审计日志、后台管理和长期维护。
- Vue 3 + Element Plus 适合快速构建管理后台、社区工作台和家庭端页面。
- MySQL 适合保存账号、授权关系、训练内容、训练记录和活动数据。
- Redis、MinIO、OpenAPI、Docker Compose 都可以在不增加过多复杂度的前提下补齐缓存、素材、接口文档和部署能力。
- 第一版不把 AI、语音、大模型对话作为核心依赖，降低交付风险。

## 技术栈

### 前端

| 类型 | 技术 |
| --- | --- |
| 框架 | Vue 3 |
| 语言 | TypeScript |
| 构建工具 | Vite |
| 路由 | Vue Router |
| 状态管理 | Pinia |
| UI 组件 | Element Plus |
| HTTP 客户端 | Axios |
| 表单校验 | Element Plus Form Rules 或 Zod |
| 图表 | ECharts |
| 测试 | Vitest、Vue Test Utils、Playwright |

前端建议拆成四类入口或页面域：

- 老年用户端：训练、复盘、求助提示，以大字体、低干扰、清晰反馈为优先。
- 家庭端：授权绑定、训练摘要、陪伴建议、提醒设置。
- 社区工作台：活动管理、课程安排、群体统计、宣教材料。
- 管理后台：用户、角色、权限、内容审核、审计日志、系统配置。

### 后端

| 类型 | 技术 |
| --- | --- |
| 语言 | Java 17 |
| 框架 | Spring Boot 3 |
| 安全 | Spring Security、JWT |
| ORM | MyBatis-Plus |
| 参数校验 | Jakarta Validation |
| API 文档 | springdoc-openapi / Swagger UI |
| 数据库迁移 | Flyway |
| 测试 | JUnit 5、Spring Boot Test、Testcontainers |
| 构建 | Maven |

后端采用单体模块化结构，先保证领域边界清晰，再根据真实压力决定是否拆服务。

建议包结构：

```text
backend/
└── src/main/java/
    └── com/eldertrust/
        ├── auth/
        ├── user/
        ├── scenario/
        ├── training/
        ├── family/
        ├── community/
        ├── content/
        ├── statistics/
        ├── audit/
        ├── storage/
        └── common/
```

### 数据与基础设施

| 类型 | 技术 |
| --- | --- |
| 主数据库 | MySQL 8 |
| 缓存 | Redis |
| 文件存储 | MinIO 或兼容 S3 的对象存储 |
| 反向代理 | Nginx |
| 容器化 | Docker、Docker Compose |
| 日志 | Logback + JSON 日志格式 |
| 监控预留 | Spring Boot Actuator |

数据库以 MySQL 为主，保存结构化业务数据；Redis 只用于缓存、验证码、限流或短期状态，不作为关键业务数据的唯一来源；MinIO 保存训练素材、图片、音频、课程附件等文件。

## 系统核心功能

### 1. 账号、角色与权限

目标：让不同角色只能访问自己应访问的数据和功能。

核心能力：

- 注册、登录、退出。
- JWT 登录态。
- 老年用户、家庭成员、社区工作者、内容管理员、系统管理员角色。
- 基于角色和资源归属的权限控制。
- 账号启用、禁用和基础资料维护。

第一版验收：

- 未登录用户不能访问受保护接口。
- 家庭成员不能查看未授权老人的训练数据。
- 社区工作者不能查看非所属范围数据。
- 管理员关键操作有审计记录。

### 2. 反诈情景训练

目标：让老年用户在模拟诈骗场景中完成识别、判断、选择和复盘。

核心能力：

- 按诈骗类型浏览训练场景。
- 支持图文对话式场景。
- 支持单选、多选、判断题。
- 支持训练过程记录。
- 支持答案解析、风险点说明和求助提示。
- 支持错题回顾和薄弱主题统计。

第一版诈骗主题建议：

- 冒充客服退款。
- 虚假投资理财。
- 保健品和养生讲座营销。
- 冒充亲友借钱。
- 中奖返利或刷单返现。

第一版验收：

- 老年用户能完成一次完整训练。
- 每次训练有结果、解析和复盘建议。
- 训练记录能用于家庭端和社区端的摘要展示。

### 3. 训练内容管理

目标：让管理员可以维护可审核、可版本化、可下线的训练内容。

核心能力：

- 诈骗主题管理。
- 场景脚本管理。
- 题目、选项、答案和解析管理。
- 内容状态流转：草稿、待审核、已发布、已下线。
- 内容版本记录。
- 素材上传和引用。

第一版验收：

- 未发布内容不会出现在用户端。
- 内容发布、下线和修改有操作记录。
- 内容至少包含主题、难度、适用人群、风险点和解析。

### 4. 家庭协同

目标：在老年用户授权的前提下，让家庭成员参与陪伴、提醒和复盘。

核心能力：

- 家庭成员绑定老人账号。
- 老年用户确认授权。
- 家庭端查看训练完成情况、薄弱主题和陪伴建议。
- 家庭提醒设置。
- 授权撤销。

隐私边界：

- 默认展示摘要，不展示逐题详细选择。
- 老年用户可以查看谁被授权。
- 授权撤销后家庭成员不能继续查看新的训练数据。

第一版验收：

- 授权前不能查看训练摘要。
- 授权后只能查看允许范围内的数据。
- 撤销授权立即生效。

### 5. 社区共育

目标：支持社区组织反诈课程、训练任务和群体复盘。

核心能力：

- 社区组织管理。
- 社区工作者账号管理。
- 活动或课程创建。
- 训练任务分配。
- 完成率、平均得分、常见错误主题统计。
- 宣教材料沉淀。

第一版验收：

- 社区工作者能创建一次活动并分配训练任务。
- 系统能展示活动完成情况。
- 默认统计为汇总数据，个人数据访问必须受权限控制。

### 6. 统计与审计

目标：让系统运行、用户访问和关键数据操作可追踪。

核心能力：

- 用户训练统计。
- 家庭端进度摘要。
- 社区活动统计。
- 内容发布记录。
- 登录、授权、导出、删除、权限变更等审计日志。

第一版验收：

- 管理员能查看关键操作日志。
- 日志不记录明文密码、完整令牌或敏感密钥。
- 统计数据能支持基础运营和课程复盘。

## 非核心但预留能力

以下能力不进入第一版必需范围，但架构上保留扩展空间：

- 语音播报和语音识别。
- AI 对话式训练。
- 基于大模型的训练脚本辅助生成。
- 小程序端。
- 短信、电话或第三方消息提醒。
- 与公安、银行、运营商等外部系统联动。

这些能力上线前必须单独评估隐私、准确性、失败降级和内容审核风险。

## 第一版交付路线

### 阶段一：工程骨架

- 建立 `frontend/` Vue 3 工程。
- 建立 `backend/` Spring Boot 3 工程。
- 建立 MySQL、Redis、MinIO 的 Docker Compose 开发环境。
- 接入 OpenAPI、基础日志和统一错误响应。

### 阶段二：账号与权限

- 完成登录、JWT、角色权限。
- 完成用户、家庭关系、社区关系基础模型。
- 建立审计日志基础能力。

### 阶段三：训练闭环

- 完成主题、场景、题目和答案解析。
- 完成用户训练、提交、结果和复盘。
- 完成错题和薄弱主题统计。

### 阶段四：协同与管理

- 完成家庭授权和家庭端摘要。
- 完成社区活动和统计。
- 完成内容审核、发布和下线。
- 完成管理后台核心页面。

### 阶段五：测试与发布

- 补齐核心单元测试、接口测试和端到端测试。
- 完成安全检查和隐私检查。
- 完成预发布环境验证。
- 准备正式部署文档和运维手册。

## 不采用方案说明

### 不以微服务作为第一版架构

当前业务边界虽然清晰，但团队早期更需要快速验证训练闭环和协同流程。微服务会增加部署、鉴权、链路追踪和数据一致性成本，第一版采用模块化单体更合适。

### 不把大模型作为第一版核心依赖

大模型可以提升对话体验和内容生成效率，但也会带来答案不可控、隐私传输、内容审核和成本问题。第一版先用可审核的固定训练内容，保证准确性和可验收性。

### 不优先开发原生 App

第一版以 Web 为主，可以覆盖管理后台、社区工作台和家庭端。老年用户端可先采用响应式 Web，后续根据实际使用场景决定是否开发小程序或原生 App。
