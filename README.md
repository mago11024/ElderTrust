# 安信伴老（ElderTrust）

面向老年人的安全受控 AI 语音反诈训练系统。

安信伴老通过固定分支学习和受控 AI 动态测评，模拟常见诈骗对话，训练老年用户识别身份伪装、保护敏感信息、抵抗情绪施压并主动核实求助。训练结束后，系统生成有证据、可解释的能力复盘；在老人明确授权后，家庭成员可以获得陪伴建议和共同训练任务。

> 当前状态：产品设计已确认，仓库处于工程实现前的文档基线阶段。第一版将采用 FastAPI 模块化单体后端，不再沿用早期 Spring Boot 方案。

## 核心创新

项目关注的不是“让 AI 把诈骗演得更像”，而是建立一套安全、可控、可评估、可持续改善的训练机制：

- 受控语音演练：AI 只能在审核过的场景阶段和话术策略内生成回复。
- 双模式训练：入门阶段使用固定分支，进阶阶段使用动态 AI 对话。
- 可解释评估：确定性规则负责最终评分，AI 只辅助理解自然语言和生成复盘。
- 家庭协同：老人先查看训练结果，再决定是否向家属分享能力摘要。
- 安全降级：云端 AI、网络或麦克风异常时，仍可降级完成训练。
- 隐私优先：不克隆真实人物声音，不默认向家属开放录音和逐字对话。

## 第一版业务闭环

```text
基础学习
→ 固定分支练习
→ AI 模拟来电测评
→ 五维能力复盘
→ 老人确认分享
→ 家庭行动卡
→ 针对性复训
→ 对比能力变化
```

五维能力包括：

1. 身份核实；
2. 信息保护；
3. 支付警觉；
4. 压力应对；
5. 求助终止。

## 首批训练场景

### 冒充客服退款

第一版旗舰场景。覆盖虚假客服身份、退款赔付、验证码、陌生链接、屏幕共享和限时施压等风险点。该场景将完整实现固定分支、动态 AI、语音对话、主动打断、能力评估和家庭行动卡。

### 保健品营销

第二个扩展场景。覆盖健康焦虑、虚假权威、成功案例、限时优惠、持续购买和隐瞒家属等诱导方式，用于验证训练引擎能否支持与客服退款不同的节奏和诈骗机制。

## 用户角色

- 老人用户：训练、测评、复盘，管理家庭授权和录音。
- 家庭成员：在授权范围内推荐训练、查看摘要、完成行动卡。
- 内容管理员：维护场景、规则、语音角色和内容版本。
- 系统管理员：管理账号、系统配置、审计和数据治理。

社区工作端不进入第一版。后续将在核心训练和家庭闭环稳定后，再扩展社区任务、课程和匿名汇总能力。

## 技术架构

```text
老人端 / 家庭端 / 管理端（Vue 3 PWA）
                │
         HTTPS / WebSocket
                │
       FastAPI 模块化单体
                │
 ┌──────────────┼──────────────┐
身份授权     训练引擎       评估复盘
场景内容     家庭协同       安全审计
                │
 MySQL / Redis / MinIO
                │
       AI 服务适配器
 ASR / LLM / TTS / 降级实现
```

主要技术：

- 前端：Vue 3、TypeScript、Vite、Pinia、Vue Router。
- 后端：Python 3.12、FastAPI、Pydantic、SQLAlchemy 2、Alembic。
- 数据：MySQL 8、Redis、MinIO 或兼容 S3 的对象存储。
- 实时通信：HTTPS API、WebSocket。
- 测试：pytest、前端单元测试、Playwright。
- 部署：Docker Compose、Nginx、HTTPS。

前端不直接调用 AI 服务。语音识别、语言模型和语音合成通过后端适配器接入，便于更换供应商并实施四级降级。

## 安全边界

第一版明确不提供：

- 真实电话外呼或未经预约的突然测试；
- 完整全双工语音；
- 真实家属、公安人员或其他个人的声音克隆；
- 自动报警、自动冻结资金或自动联系外部机构；
- 基于真实订单、健康档案或家庭隐私生成诈骗话术；
- 家属默认查看完整录音或逐字对话。

检测到“已经转账”“正在提供验证码”等疑似真实受骗表达时，系统退出诈骗角色并进入安全求助流程。只有在老人事先授权且当次确认后，才向指定家属发送求助。

## 四级降级

| 等级 | 对话 | 语音 | 评分 |
| --- | --- | --- | --- |
| L1 | 动态 AI | 实时合成 | 规则 + AI 辅助分析 |
| L2 | 固定分支 | 实时合成 | 规则评分 |
| L3 | 固定分支 | 预录语音 | 规则评分 |
| L4 | 文字与按钮 | 无语音 | 规则评分 |

答辩版本同时准备公网演示和不依赖公网 AI 的本地降级包。

## 开发路线

1. 文字版客服退款训练、状态机和规则评分。
2. ASR、TTS、自动轮流和固定分支练习。
3. 受控 AI 动态测评和五维复盘。
4. 家庭绑定、分级授权、分享确认和行动卡。
5. 模拟来电、主动打断和多语音角色。
6. 保健品营销场景和轻量内容管理。
7. 公网部署、四级降级、安全测试和答辩演示包。

每个阶段都必须交付一个可运行版本。详见[项目路线图](docs/ROADMAP.md)。
